### 3. Today's topic: semantic search

The central topic is the difference between:

1. **Vector-based semantic search**
2. **Graph-based semantic search**

The discussion is motivated by the recent addition of **vector indexing and vector search capabilities to Neo4j**, allowing vector and graph approaches to be used together.

### 4. What "semantic similarity" means

* Traditional/string search looks primarily at whether words are similar or match syntactically.
* **Semantic similarity** instead considers whether two things have similar meanings or concepts.
* The transcript uses **apple and orange** as an example:

  * They are different words.
  * They are semantically related because both are fruits.
* Semantic similarity can therefore be represented in different ways depending on how knowledge is represented.

### 5. Two ways of representing knowledge

#### Graph/symbolic representation

* Knowledge is represented explicitly using concepts and relationships.
* For example:

  * Apple → Fruit
  * Orange → Fruit
* A graph or ontology provides explicit context explaining why concepts are related.
* This is generally more **human-curated and controlled**.
* It can require domain expertise and effort to build.

#### Vector representation

* Knowledge is represented as numerical vectors/embeddings.
* Machine-learning models learn these representations from large amounts of data.
* Concepts that frequently occur in related contexts tend to have vectors that are close together.
* For example, embeddings for apple, orange, fruit, pear, and plum may be located relatively close to one another.
* The individual numbers in a vector aren't normally meaningful to humans; what matters is the mathematical relationship/distance between vectors.
* This approach can be highly automated and can operate over enormous amounts of information.

### 6. Main difference between the approaches

The transcript emphasizes that both approaches capture semantics but in fundamentally different ways.

| Graph-based                                  | Vector-based                                                     |
| -------------------------------------------- | ---------------------------------------------------------------- |
| Explicit relationships                       | Implicit relationships                                           |
| Human/domain curated                         | Learned from data                                                |
| More control                                 | More automation                                                  |
| Can explain why things are related           | Usually gives a similarity score without an inherent explanation |
| Relationships are represented as graph paths | Relationships are represented as distances between vectors       |
| Requires building/maintaining knowledge      | Can be generated automatically from large datasets               |

The speakers repeatedly emphasize that this isn't necessarily a choice between one or the other—the **combination of both can be particularly useful**.

### 7. Building the graph example

The hands-on demonstration starts with a collection of technical articles.

The process is:

1. Import articles from a CSV file.
2. Create Article nodes containing things such as:

   * URI
   * Title
   * Body
   * Timestamp
3. Import a taxonomy/ontology based on **Wikidata**.
4. Use Neo4j's semantic capabilities to represent the taxonomy as a graph.
5. Extract entities from the article text.
6. Link those entities to the corresponding concepts in the taxonomy.
7. This gives the articles additional semantic context.

### 8. Entity extraction and linking

* Natural-language-processing services can extract entities from article text.
* In the example, Google Cloud's NLP service was used.
* The extracted entities are associated with Wikidata/Wikipedia identifiers.
* Those identifiers make it easier to connect extracted entities to the existing taxonomy.
* This creates a bridge between unstructured text and the structured knowledge graph.

### 9. Cleaning the taxonomy

* The imported Wikidata taxonomy may contain redundant relationships.
* For example, if:

  * Blood orange → Orange → Fruit
* there may also be a direct:

  * Blood orange → Fruit
* The demonstration removes some redundant relationships to make the taxonomy cleaner.

### 10. Creating vector embeddings

* The body of each article is converted into a vector embedding.
* The example uses an OpenAI embedding model.
* The embeddings are stored as properties on the Article nodes.
* Neo4j's **vector index** is then used to index those embeddings.
* Cosine similarity is used to compare vectors.

### 11. Vector similarity between two articles

* Two articles are selected.
* Their embeddings are compared using cosine similarity.
* The result is a numerical similarity score.
* This is useful for determining that two articles are similar.
* However, the vector similarity score doesn't inherently explain **why** the articles are similar.
* Users therefore have to trust the embedding model and the data used to create it.

### 12. Graph-based similarity between articles

The same articles can instead be compared through the knowledge graph.

* Articles are connected to extracted concepts.
* Those concepts are connected through the taxonomy.
* A path can therefore connect two articles.
* The length/structure of that path can be used to calculate semantic similarity.
* More importantly, the actual path can be returned.

For example, two articles might be connected because:

* Article A → Neo4j → Graph Database → Database Management System
* Article B → Couchbase → Document Database → Database Management System

That path provides an **explanation** for their semantic similarity.

### 13. Explainability is a major advantage of graph search

The speakers highlight that graph-based similarity can answer:

> "Why are these two things considered similar?"

Instead of simply saying that two articles have a similarity score, the graph can show the relationships that produced the result.

This gives:

* Explainability
* Greater control
* Visibility into the reasoning path
* Ability to constrain how similarity is calculated

This becomes especially important for higher-stakes applications where simply trusting a model's output may not be sufficient.

### 14. Vector semantic search

The demonstration then moves from comparing two known articles to actual search.

* One article's embedding is used as the query.
* Neo4j's vector index finds the nearest article embeddings.
* The top results are returned based on vector similarity.
* The article itself is excluded because it would otherwise be the closest match to itself.
* This provides a typical **semantic search/recommendation** mechanism.

The advantage is that it can discover similarities that aren't obvious from exact word matching.

### 15. Graph-based search can be customized

The graph approach allows domain-specific knowledge to be added.

The demonstration adds additional knowledge about **software stacks**, such as:

* LAMP
* MEAN
* MERN/related stacks
* Other technology combinations

This changes the paths available through the graph.

As a result, articles that previously weren't considered especially similar can become more closely related because the newly added domain knowledge creates an additional connection.

### 16. The key distinction: learned vs. curated knowledge

A central message is:

**Vector search depends on what the embedding model learned from its training data.**

**Graph search depends on knowledge that has explicitly been represented and curated.**

With the graph:

* You decide what relationships exist.
* You can add domain-specific knowledge.
* You can remove or block relationships.
* You can explain the resulting similarity.

With vectors:

* The model can discover relationships automatically.
* It scales well to huge amounts of information.
* But the reasoning behind a particular similarity isn't directly represented.

### 17. Combining the two approaches

The speakers argue that the powerful approach is often to **combine vector and graph techniques**.

Vectors can provide:

* Broad semantic discovery
* Automated representation
* Efficient nearest-neighbor search

Graphs can provide:

* Context
* Domain knowledge
* Control
* Explainability
* Explicit relationships

The combination can therefore provide both **scale/discovery and controlled context/explanation**.

### 18. Tomato example

One host gives an example involving **tomatoes**.

* Botanically, a tomato is a fruit.
* In a conventional ontology, it may therefore be classified under "fruit."
* But in a practical context such as "what belongs in a fruit salad?", that classification alone isn't sufficient.
* Vector similarity might also place tomatoes near other foods based on learned relationships.
* Additional contextual knowledge can be added to the graph to distinguish different contexts.

The broader point is that **meaning depends on context**, and graphs can explicitly encode that context.

### 19. Multiple paths between articles

A question asks whether there can normally be multiple paths between articles.

The answer is **yes**.

An article may mention multiple concepts, and each concept can provide a different connection to another article.

More curated knowledge can therefore create:

* More paths
* More possible explanations
* Richer semantic relationships
* More ways to control the search

### 20. Importance of explainability

The speakers agree that explainability can be particularly important when results influence important decisions.

For low-stakes use cases, an incorrect recommendation may simply mean someone doesn't click an article.

For higher-stakes situations—such as:

* Investment decisions
* Medical decisions
* Other consequential decisions

—it can be important to know **why** a system produced an answer.

### 21. Spatial/geographical similarity

A question asks about using these techniques for property records and spatial similarity.

The response notes that:

* Vector indexes use approximate nearest-neighbor techniques.
* Spatial information can also be represented/indexed separately.
* Geographic proximity could potentially become another component of an overall similarity calculation.
* The graph can combine different types of contextual information.

### 22. Vector index availability

The vector index feature demonstrated is described as a **beta feature** at the time of the presentation.

* It is available in Neo4j editions at that point.
* Neo4j Sandbox can be used to experiment with it.
* The speakers recommend using a sufficiently recent Neo4j version.

### 23. Final takeaway

The overall message of the presentation is:

> **Semantic search isn't one single technique.**

There are at least two important approaches:

* **Vector-based semantic search:** learned, numerical, scalable, automated.
* **Graph-based semantic search:** explicit, curated, contextual, explainable.

Neither approach is presented as universally superior. The main recommendation is to understand the strengths and limitations of both and consider **using them together** when the application benefits from both semantic discovery and explicit domain context.
